「데스티네이션 어스」 검증-수정 루프를 실행하라. **모든 검사가 통과할 때까지 [검증→수정→재검증] 반복, 최대 3회.** 3회 후에도 실패가 남으면 중단하고 남은 실패와 원인 분석을 보고하라(무한 루프 금지).

## 검증 기준 (전부 통과 = 성공)
1. 변경된 모든 `.js`(git diff --name-only HEAD, 생성물 제외)에 `node --check` 통과
2. `node scripts/i18n-parity.js` → "✅ 모든 로케일 키 일치"
3. `node -e "require('./package.json')"` 통과 (수정된 경우)
4. `git status --short`에 커밋 금지 대상 없음: dist/·mobile-www/·android/·*.keystore·el_key·_*.cjs·.bak
5. (UI/로직 변경 시) 프리뷰 스모크: preview_start → 새 게임 진입 → 콘솔 에러 0 → 데스크톱(1280×800)과 모바일(844×390, body.is-mobile) 양쪽 렌더 확인

## 규칙
- 실패 발견 시 **원인을 직접 수정**하고 해당 검사만이 아니라 **전체 시퀀스를 재실행**한다(수정이 다른 검사를 깰 수 있음).
- 검증 통과를 위장하지 말 것 — 헤드리스에서 확인 불가한 항목(음색·전투 연출)은 "실기 확인 필요"로 명시.
- 완료 보고: 검사별 ✅/❌ 표 + 반복 횟수 + 수정한 내용 요약.
