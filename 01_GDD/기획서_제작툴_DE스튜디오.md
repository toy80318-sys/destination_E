# 기획서 — DE 스튜디오 (게임 제작·튜닝 툴) (2026-07-05)

> 목적: 데스티네이션 어스의 **개선·디벨롭 속도를 올리는 자체 제작 툴**.
> 대상 플랫폼: 데스크톱(Steam)·웹 + **iOS/Android(모바일 버전) 개발 지원 내장**.
> 결론 먼저: 새 엔진/외부 툴 도입이 아니라 **브라우저 기반 인하우스 에디터**(기존 `ui-editor.html` 확장 노선)로,
> `js/data/` 테이블을 GUI로 편집 → 게임 iframe에 **핫 리로드 주입** → 시뮬레이터로 밸런스 즉시 검증하는 구조가 최적.

---

## 1. 리서치 결론 — 왜 이 방식인가

2026년 웹게임 개발의 주류는 "엔진 없는(engine-free) 데이터 주도 게임 + **게임에 데이터를 공급하는 커스텀 브라우저 에디터**" 패턴이다. 상용 에디터(GDevelop·Construct 등)는 런타임까지 종속되므로 이미 완성된 본 게임에는 부적합하다.

| 선택지 | 평가 |
|---|---|
| **인하우스 브라우저 에디터 (권장)** | ✅ 기존 바닐라 스택과 동일, 설치 0, 게임 자체를 미리보기로 임베드 가능. `ui-editor.html`(623줄)로 이미 검증된 노선 |
| 상용/오픈소스 게임 에디터 도입 | ❌ 런타임 종속·마이그레이션 비용. 완성 단계 게임에 과잉 |
| Electron 별도 툴 앱 | △ 가능하나 브라우저판이면 충분. 필요 시 후속으로 래핑만 |
| 스프레드시트(구글시트) 연동 | △ 협업엔 좋으나 1인 개발 + 로컬 파이프라인엔 왕복 비용만 증가 |

**본 프로젝트의 결정적 이점 (이미 갖춘 것):**
- `js/data/` **21개 데이터 테이블** (planets·ships·heroes·parts·quests 6페이즈·commodities·factions·crafting·voice-map 등) — 편집 대상이 이미 코드와 분리됨
- `ui-editor.html` — 브라우저 에디터 선례
- `scripts/mobile-audit.js`·`mobile-screenshot.js` — puppeteer 검증 인프라
- dev-loop 하네스의 **시뮬레이션 스크립트**(전투/경제/세이브) — 밸런스 검증 엔진으로 재사용 가능
- 인게임 dev-menu — 툴 ↔ 게임 브리지 진입점

## 2. 툴 정체성

**이름:** DE 스튜디오 (`de-studio.html` + `scripts/de-studio-server.js`)
**한 줄 정의:** "js/data 테이블을 안전하게 편집하고, 그 결과를 게임·시뮬레이터·모바일 프리뷰로 즉시 확인하는 통합 작업대."
**사용자:** 개발자 본인(1인) + AI 에이전트(dev-loop 하네스가 같은 데이터 계약을 공유).

## 3. 아키텍처

```
┌─ 브라우저 ──────────────────────────────────────────────┐
│  de-studio.html (SPA, 바닐라 JS — 게임과 동일 스택)      │
│  ┌──────────┬───────────────┬──────────────────────┐   │
│  │ ① 데이터  │ ② 라이브       │ ③ 검증               │   │
│  │   에디터  │   프리뷰       │   시뮬레이터          │   │
│  │ (테이블/  │ (게임 iframe + │ (전투·경제·드롭률     │   │
│  │  폼 뷰)   │  핫 데이터주입) │  몬테카를로)          │   │
│  └──────────┴───────────────┴──────────────────────┘   │
└──────────────────────┬──────────────────────────────────┘
                       │ HTTP (localhost 전용)
┌──────────────────────▼──────────────────────────────────┐
│ scripts/de-studio-server.js (Node, 의존성 0)             │
│  · GET /data/:table   → js/data/*.js 파싱해 JSON 반환    │
│  · POST /data/:table  → 검증(스키마) → 백업 → 파일 기록   │
│  · POST /sim/:kind    → 시뮬레이션 실행 → 결과 JSON      │
│  · git diff 요약 반환 (변경 리뷰용)                       │
└─────────────────────────────────────────────────────────┘
```

**핵심 설계 원칙**
1. **파일이 곧 진실** — 툴은 DB를 두지 않는다. `js/data/*.js`를 직접 읽고 쓴다(포맷 보존 직렬화). git이 버전 관리를 담당 → dev-loop 하네스와 충돌 없음.
2. **스키마 게이트** — 테이블별 JSON 스키마(타입·범위·필수 필드·참조 무결성: 예 퀘스트가 참조하는 planetId 존재 확인)를 서버가 강제. 잘못된 데이터는 저장 자체가 안 됨.
3. **저장 전 자동 백업 + diff 미리보기** — 저장 시 `.bak` 생성, 변경 diff를 툴에서 확인 후 확정.
4. **localhost 전용** — 서버는 127.0.0.1 바인딩 + 외부 노출 금지. 비밀키 취급 없음.
5. **게임 무변경 원칙** — 게임 쪽엔 dev-menu에 "스튜디오 데이터 리로드" 훅 1개만 추가(있어도 일반 유저에겐 비활성).

## 4. 기능 명세 (모듈별)

### ① 데이터 에디터 (MVP 핵심)
- 테이블 선택 → 그리드 뷰(행=엔티티) + 행 클릭 시 폼 뷰(필드별 위젯: 숫자 슬라이더+범위, enum 드롭다운, 이미지 경로는 썸네일 미리보기).
- 일괄 편집: 열 단위 수식 적용(예: "티어2 함선 HP 전부 ×1.1") — 밸런스 패스에 필수.
- 참조 네비게이션: 퀘스트→행성→상품처럼 ID 참조를 클릭으로 따라가기.
- i18n 병행 편집: 엔티티의 ko/en 텍스트를 한 화면에서 (기존 `i18n/ko.js`·`en.js` 연동, 저장 시 `verify-i18n-live.js` 자동 실행).

### ② 라이브 프리뷰
- 게임을 iframe으로 임베드(`?dev=1&studio=1`), 편집한 테이블을 postMessage로 주입 → **새로고침 없이** 수치 반영(dev-menu 훅 경유).
- **모바일 프리뷰 (iOS/Android 지원의 핵심):**
  - 뷰포트 프리셋: iPhone 15/SE·Galaxy S24·태블릿 (가로 고정, 세이프에어리어 인셋 시뮬레이션 오버레이)
  - `body.is-mobile` 강제 토글 → 바텀시트·드로어·터치 타깃을 데스크톱에서 즉시 확인
  - 터치 타깃 검사기: 44/48px 미달 요소 하이라이트 (mobile-audit.js 로직 재사용)
- 스크린샷 버튼: 현재 프리뷰를 FHD/모바일 해상도로 캡처(스토어 스크린샷 제작 겸용, puppeteer 재사용).

### ③ 검증 시뮬레이터
- **전투 시뮬**: 함선/파츠/영웅 조합 vs 적 편성 → N회 몬테카를로 → 승률·평균 턴·데미지 분포. (전투 공식을 Node로 격리 실행 — dev-loop G3 시뮬 자산 재사용)
- **경제 시뮬**: 행성 순회 무역 마진·세금 수입 곡선 → 페이즈별 크레딧 성장 그래프.
- **가챠/드롭 시뮬**: 설계도·영웅 획득 기대 횟수(예: 거북선 단편 20% 확률의 실측 분포).
- 결과는 편집 전/후 비교로 표시 → "이 수치 변경이 승률을 몇 %p 움직였나"를 즉시 확인.

### ④ 콘텐츠 저작 (2차)
- 퀘스트 카드 편집기: phase1~6_quests.js를 카드 UI로, 선행조건 그래프 시각화.
- 컷신/대사 편집기: 씬 메타 + 음성 매핑(voice-map) + 미리듣기.
- 도감 lore 편집 + 누락 검사(이미지·음성·번역 누락 리포트).

### ⑤ 모바일 빌드 패널 (2차)
- `npm run mobile:www` 실행 버튼 + 번들 용량 리포트(150MB 목표 대비 게이지).
- 에셋 다이어트 결과 비교(원본 vs mobile-www) 및 초과 파일 톱10.
- Android/iOS 빌드는 스토어 정책상 로컬 PC(Android Studio/Xcode) 필요 — 툴은 체크리스트·명령 복사 UI 제공까지.

## 5. 구현 로드맵 (dev-loop 백로그 투입 단위)

| 단계 | 항목 | 산출물 | 난이도 |
|---|---|---|---|
| T1 | 서버 골격 + planets/ships/heroes 읽기·검증·백업·쓰기 | `scripts/de-studio-server.js` | 중 |
| T2 | 데이터 에디터 UI(그리드+폼) + diff 미리보기 | `de-studio.html` | 중 |
| T3 | 게임 iframe + 핫 주입(dev-menu 훅) | dev-menu 소폭 확장 | 중 |
| T4 | 모바일 프리뷰(뷰포트 프리셋·is-mobile 토글·터치 타깃 검사) | 〃 | 하 |
| T5 | 전투 시뮬레이터(몬테카를로) + 전/후 비교 | `/sim/combat` | 상 |
| T6 | 경제·드롭 시뮬레이터 | `/sim/economy`·`/sim/gacha` | 중 |
| T7 | i18n 병행 편집 + 누락 리포트 | 〃 | 중 |
| T8 | 퀘스트/컷신 편집기 | 〃 | 상 |

- T1~T4 = **MVP** (여기까지만 해도 밸런스 튜닝·모바일 UI 확인 체감 효과 큼)
- 각 단계는 dev-loop 사이클 1~2건 크기로 분해해 백로그 투입 → 기존 하네스(G1~G6 게이트)로 품질 보장.

## 6. 안전 규칙 (하네스 연동)

- 툴이 저장하는 모든 데이터 변경도 **git 커밋 전 diff 리뷰** 대상 — 툴은 커밋하지 않는다(사람 또는 Director가 커밋).
- **밸런싱 수치의 "결정"은 여전히 사람 몫** — 툴은 수치를 바꾸기 쉽게 하고 결과를 보여줄 뿐, dev-loop가 자동으로 밸런스를 바꾸는 데 쓰지 않는다(CLAUDE.md 규칙 유지).
- `de-studio.html`·서버는 **빌드 제외**(`build.files`에 포함 금지, dist/모바일 번들에 절대 미포함).
- 서버는 localhost 전용, 저장소 밖 경로 쓰기 금지(경로 화이트리스트: `js/data/`, `i18n/`).

## 7. 리스크

- `js/data/*.js`가 JSON이 아닌 JS 리터럴 → 포맷 보존 파서 필요(주석·키 순서 유지). 대응: 테이블별 "파싱→편집→재직렬화" 왕복 테스트를 T1 완료 기준에 포함.
- 전투 공식이 game.js/combat.js에 분산 → 시뮬레이터가 로직을 복제하면 이중화 위험. 대응: 공식을 함수 단위로 추출해 게임과 시뮬이 **같은 코드**를 로드(vm 컨텍스트) — 복제 금지.
- 툴 개발이 게임 개발을 잠식할 수 있음 → MVP(T1~T4) 이후는 실사용 빈도를 보고 계속 여부 결정.
