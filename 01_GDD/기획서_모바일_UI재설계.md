# 기획서 — DESTINATION EARTH 모바일 UI 재설계 (2026-06-28)

> 목적: 기존 데스크톱/와이드 UI를 **모바일(iOS·Android)에 적합한 화면 구성**으로 재설계.
> 선행: `기획서_모바일포팅_iOS_Android.md`(래핑 방식·로드맵) + 1단계 완료(세이프에어리어·타이틀 터치, beta.341).
> 결론 먼저: **Capacitor 래핑 + 가로(landscape) 고정** 유지 + **터치 우선 화면 재구성**(사이드바→드로어/하단탭, 모달→바텀시트, 밀집 그리드→카드/세로 스택, 주요 액션→엄지존 하단바).

---

## 1. 최적 방법 (글로벌 리서치 반영)

| 결정 | 내용 | 근거(리서치) |
|---|---|---|
| **래핑** | Capacitor (Electron의 모바일판) | WebView 게임 표준, canvas/WebGL 지원, 한 코드베이스로 웹·Steam·iOS·Android |
| **방향** | **가로 고정** (`@capacitor/screen-orientation` 또는 capawesome) | 현 UI가 와이드 HUD 기반 → 가로가 재작업 최소. iPad는 Info.plist `Requires Full Screen=YES` 필요 |
| **성능** | 단일 거대 번들 회피·minify·브리지 호출 최소화 | WebView는 JS/CSS/HTML 효율이 곧 체감 성능 |
| **레이아웃 철학** | "반응형(요소 재배치)" + "적응형(레이아웃 자체 교체)" 병행 | 데스크톱→모바일은 CSS만이 아니라 **콘텐츠·상호작용 재설계** |

> ⚠ 본 게임은 **고정 스테이지(1500×750)를 transform:scale+회전으로 contain-fit** 하는 구조. 완전 세로(portrait) 리플로우는 사실상 전면 재작성 → **가로 고정 + 스테이지 내부 터치 재구성**이 비용 대비 최선. (세로 대응은 후순위 별도 과제)

## 2. 모바일 디자인 원칙 (터치·엄지·가독)

- **터치 타깃**: 최소 44×44pt(iOS) / 48×48dp(Android) + 타깃 간 간격 확보.
- **엄지존**: 화면 **하단 1/3 = 가장 닿기 쉬움**, 중앙=보통, 상단 모서리=불편. → **주요 액션 버튼은 하단**.
- **하단 내비**: 핵심 3~5개만. 현재 선택 항목은 색/굵기/밑줄로 표시.
- **밀집 데이터**: 표 → **스와이프 카드 / 세로 key-value 스택**.
- **모달**: 화면 꽉 채우는 **바텀시트 + 큰 닫기(X)**. (이미 모바일 모달은 버튼 상단 이동·56px 적용)
- **익숙한 패턴 사용**(탭바·햄버거·바텀시트) — 새 내비 발명 지양.
- **브레이크포인트**: 모바일 판정 = `(pointer:coarse)` 또는 짧은 변 ≤ ~480px. (기존 `@media (max-width:768px),(pointer:coarse)` 활용)

## 3. 화면별 재설계 (Before → After)

### 3-1. 허브 메인 (사이드바 + HUD + 본문 + 백구바)
- **현재**: 좌측 세로 사이드바(269px) + 상단 HUD + 본문 + 하단 백구 대화바. 가로폭을 사이드바가 잠식.
- **모바일안**:
  - 사이드바 → **좌측 햄버거 드로어**(평소 숨김, 햄버거 탭 시 슬라이드 인) **또는** **하단 탭바 5종**(메인시티·행성광장·정비소·퀘스트·도감). → 권장: **하단 탭바**(엄지존) + 더보기는 드로어.
  - 상단 HUD: 자원 칩 축약(아이콘+숫자), 길게 누르면 상세 툴팁.
  - 백구 대화바: 기본 **접힘(30px)** + 탭 시 펼침(시트). 전투/컷신 중 자동 접힘.

### 3-2. 퀘스트 탭
- 카드 2~3열 → 모바일 **1~2열, 카드 높이↑, 수락 버튼 카드 하단 풀폭**.
- 긴 설명은 ‘더보기’ 접기.

### 3-3. 정비소(편대·파츠·크루) — ⚠ 최고 난도(밀집)
- 좌(함선 정보) + 우(파츠 그리드/서브탭) 2열 → 모바일 **상하 스택 또는 세그먼트 탭**(정보 / 파츠 / 크루 / 화물 전환).
- 파츠 격자 셀 41px → 터치용 ≥48px, 드래그 대신 **탭→장착 슬롯 선택** 보조.

### 3-4. 도감 / 경매 — 밀집 리스트
- 그리드 → **세로 카드 리스트**(썸네일+이름+핵심 스탯), 상세는 바텀시트.
- 경매 입찰 버튼은 시트 하단 고정.

### 3-5. 전투 HUD
- 함대 전술(학익진·일점사 등) 스킬 버튼을 **화면 하단 좌우 엄지영역**에 큰 버튼으로.
- 체력/쉴드 게이지·전투력 폰트 확대, 적/아군 함선 탭 영역 확대.

### 3-6. 스타맵
- **핀치 줌 + 드래그 팬**, 행성 노드 탭 영역 확대(히트박스 ≥48px).

### 3-7. 컷신 / 프롤로그
- 현행 풀스크린 + 큰 자막 양호. **탭=다음, 길게=스킵**, 하단 진행 점(•••) 표시.

### 3-8. 공통 모달 → 바텀시트
- 작은 정보 모달은 화면 하단에서 올라오는 시트 + 스와이프 다운 닫기.

## 4. 디자인 시스템 (모바일 토큰)
- CSS 변수: `--touch-min:48px`, `--m-gap:12px`, `--sheet-radius:16px 16px 0 0`.
- 모바일 클래스 게이트: `body.is-mobile`(JS가 `(pointer:coarse)`·화면크기로 부여) → 기존 `@media` 보완(스테이지 내부라 vw 미디어쿼리 한계 → JS 클래스 병행).
- 세이프에어리어: `env(safe-area-inset-*)` (스테이지 스케일은 §1단계에서 `_safeInsets` 적용 완료).

## 5. 구현 단계 (코딩 순서)
1. **모바일 모드 토큰/판정** — `body.is-mobile` 부여(JS), 디자인 토큰 CSS, 기존 @media 통합.
2. **허브 내비 재구성** — 사이드바 → 하단 탭바(+드로어). (가장 큰 체감 변화)
3. **모달 → 바텀시트** 스타일 + 큰 닫기.
4. **정비소/도감/경매 밀집 화면** 세그먼트 탭·카드화. (가장 손 많이 감)
5. **전투 HUD 엄지존 배치** + 스타맵 핀치줌.
6. **Capacitor 스캐폴드** — Android(이 PC 가능) / iOS(Mac 필요) + 가로고정·스플래시·아이콘.
7. **실기 테스트 → 폴리시 → 스토어 준비**.

> 각 단계는 데스크톱(Steam/웹) 동작을 **회귀 없이** 유지(모바일 분기만 추가). `body.is-mobile` 게이트로 데스크톱 경로 불변.

## 6. 리스크
- 정비소·도감·경매 = 정보 밀도 최고 → 재배치 비용 큼(§5-4).
- 고정 스테이지 구조상 완전 세로 리플로우는 후순위.
- 번들 용량(다국어 음성·이미지) → 온디맨드/압축 필요.
